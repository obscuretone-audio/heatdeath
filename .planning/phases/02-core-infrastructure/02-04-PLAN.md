  // CHAIN-02: 4x polyphase IIR oversampling wrapping Stage 1 RAT at plugin boundary.
  // Stages 3 and 4 will add their own stage-internal oversampling in Phases 5 and 6;
  // for Phase 2 the single plugin-level oversampler is sufficient because all stages
  // are pass-through stubs.
  juce::dsp::Oversampling<float> oversampler {
      1u,                                                                 // numChannels (mono at boundary)
      2u,                                                                 // factor order = 4x
      juce::dsp::Oversampling<float>::filterHalfBandPolyphaseIIR,
      true,                                                               // max quality
      false                                                               // do not interleave
  };

  // WR-03: Per-sample linear interpolation of feedback injection across the block
  // avoids the step artefact at block boundaries. Holds previous block's feedback.
  float previousFeedbackSample = 0.0f;

  // PARAMS-04 at the processor level for the three trim controls.
  // 20ms smoothing window per the smoothing spec.
  juce::SmoothedValue<float> trimPostRatSmooth;
  juce::SmoothedValue<float> trimPostPitchSmooth;
  juce::SmoothedValue<float> trimPostUndSmooth;

JUCE Oversampling API usage:
  ctor args: (numChannels, factor_order_log2, filter_type, max_quality, use_integer_latency)
  in prepareToPlay:
    oversampler.reset();
    oversampler.initProcessing(static_cast<size_t>(samplesPerBlock));
    setLatencySamples(static_cast<int>(oversampler.getLatencyInSamples()));
  in processBlock (around Stage 1):
    juce::dsp::AudioBlock<float> monoBlock(buffer.getArrayOfWritePointers(), 1, numSamples);
    auto osBlock = oversampler.processSamplesUp(monoBlock);
    // stage processes at 4x rate — for Phase 2 stub it still passes through correctly
    // ... stageTurboRat->process(...) — signature takes AudioBuffer, so we will
    //     either (a) wrap osBlock in a temporary AudioBuffer view or
    //     (b) skip the stage call while oversampled and do it at native rate.
    oversampler.processSamplesDown(monoBlock);

  For Phase 2 (pass-through stages) we use the simplest correct approach:
  perform the up/down around an empty 4x-rate window so the oversampler's
  anti-alias filters are exercised and their latency is reported, but the
  TurboRat stub is still invoked at native rate on the downsampled buffer.
  Per the stage-internal oversampling note in RESEARCH.md A2, this keeps the
  architecture compatible with Phases 5 and 6 which will move oversampling
  into the stages themselves.
